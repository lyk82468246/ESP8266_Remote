# 固件与硬件规则

## 板级配置和驱动

- GPIO 使用芯片编号，不能把 Dx 标签当成 GPIO 编号。默认 D4 = GPIO2、低电平有效；更换板型、外设或电平时核对板卡资料并记录假设。
- 实际外设统一在 `Config.h` 的 `kResources` 注册，能力描述、API 路由和状态由同一注册表生成。当前为板载 LED + 四只外接 LED + A0 电位器；电机缺驱动及额定参数，光敏由用户决定延后，不得虚构相应可控资源。
- 最多 8 个资源、每项最多 4 个属性，当前 Binary/Pwm 各一个属性、Analog 为 raw 与 voltage 两个只读属性。先验证全部 ID、属性名、重复 GPIO、单 A0 占用和数值约束，再初始化引脚。GPIO6–11 为 flash，GPIO1/3 留给串口；GPIO0/2/15 的启动电平要求需核验。
- PWM 默认 1 kHz、0–100% 整数步长，使用固定 Core 版本的 waveform API 确认配置成功/失败，0/100% 采用静态电平。它不是光学亮度或转速反馈。所有外接 LED（含 PWM）每只独立限流电阻。
- 用户指定电位器使用 3.3 V，软件以 1024 对应 3.3 V 换算板端估算电压，保留三位小数；这不是硬件校准或耐压测量。raw 保留 SDK uint16 原始计数，超过标称量程仍显示原始值，voltage 不作超量程外推。A0 裸芯片 0–1 V 与板级分压必须区分，软件状态不是过压报警。250 ms 定时采样，HTTP 不触发采样；首次/无效值返回 null/unavailable，不把 good 当成断线检测。
- GPIO 操作集中在驱动。上电先设置关闭电平，再启用输出；不恢复上次目标。灯光演示断联保持当前值。新增需要失联保护的外设时明确其保护行为并实现验证。
- 返回的是驱动确认的逻辑输出，不是实际亮度或触点反馈。回读失败返回驱动错误并尝试还原，不承诺物理故障时还原必然成功。

## 网络、容量和配置

- 默认 STA 加入手机热点/普通 WLAN；SoftAP 由 `nodemcuv2_ap` 显式选择。SSID 未配置时关闭网络并保持输出关闭，不自动回退热点。连接与重连不能长期阻塞主循环；串口输出实际 DHCP 地址，不打印真实密码。
- 两种模式广播 `_wifi-control._tcp`，实例包含 deviceId，TXT 提供 protocolVersion/deviceId。mDNS 更新放在主循环 HTTP 提前返回之前；断线/IP 变化后重建，失败限频重试，不能禁用手动 IP 控制。
- 显示名按 1–64 个 Unicode 字符校验，不能全空白或含 C0/C1 控制字符，拒绝无效 UTF-8；设备、外设和属性名都需验证，验证通过前不触碰 GPIO。
- 用户明确要求固定的项目 WiFi 参数保存在 `ESP8266_Remote/WiFiConfig.h` 并纳入版本管理，不使用 config.local.h 或对应忽略规则。该授权仅针对本项目这组网络配置；其他未授权私密信息仍不进入 Git。串口和 API 不输出密码。
- 保留固定容量和有界处理：请求体 1024 字节、头部 2048 字节、单行 255 字节、当前响应 4 KiB，接收每轮最多 256 字节。容量变化需评估静态 RAM 与运行时堆，协议响应不能超过 16 KiB。
- 保留接收和发送超时，慢客户端不得无限占用设备。传感器扩展通过主循环采样和缓存，HTTP 读取缓存，不能在请求内长时间等待采样。
- 新增属性类型时同时实现描述、校验、驱动、状态质量和契约测试；不要仅靠增加 capability JSON 宣称支持。
