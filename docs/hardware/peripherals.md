# NodeMCU V3 外设接线与控制

用户提供板卡文字：`LOLIN / wemos.cc / NEW NodeMCU V3`。使用现有 `nodemcuv2`（ESP-12E/ESP8266）构建基线；实际板卡未拍照或实测，不以该标识保证 A0 分压电路与原版完全一致。接线前断开电源。

## 安卓类型与本轮范围

| 外设 | 安卓分类与属性 | 本轮状态 |
| --- | --- | --- |
| 红、绿开关 LED | binary-output；boolean on | 已实现，两路独立 |
| 红、绿调光 LED | range-output；integer level，0–100%，step=1 | 已实现，两路独立，1 kHz 软件 PWM；对应开关灯关闭时跟随电位器 |
| 电位器 | sensor；只读 integer raw + number voltage（V） | 已实现，两项来自唯一 A0 的同一缓存 |
| 微波感应开关 | sensor；只读 boolean detected + integer offDelayMs（ms） | 已实现，假定 D7 接常开继电器干接点；接线类型尚待实测 |
| 两线直流电机 | range-output，可用范围属性表示 PWM 占空比 | 缺少驱动与电机规格，本轮不注册、不分配输出 |
| 光敏器件 | sensor，具体属性依器件/电路确定 | 按用户决定延后，不与电位器并接 A0 |

板载 LED 保留，因此当前共 7 个资源，不是 8 个虚构外设。上位机按属性描述生成开关、滑块和只读值，无需写死本表 ID。上位机依据：[功能清单规范](https://github.com/zxu-source/Android_WIFI/blob/320f9c00b35aa7c80edd5911832b7a2ccd5c1c3b/docs/protocol/capability-list.md)。

## 引脚表

| 板上标记 | GPIO | 用途 | API 资源 / 属性 |
| --- | --- | --- | --- |
| D4 | 2 | 板载 LED，低电平亮，无需外接 | led.main / on |
| D1 | 5 | 第一只红 LED，开关 | led.red / on |
| D2 | 4 | 第一只绿 LED，开关 | led.green / on |
| D5 | 14 | 第二只红 LED，PWM | pwm.red / level |
| D6 | 12 | 第二只绿 LED，PWM | pwm.green / level |
| D7 | 13 | 微波开关干接点输入，内部上拉，低电平有效 | sensor.microwave / detected、offDelayMs |
| A0 | ADC | 电位器滑动端信号，经下述电压限制 | sensor.pot / raw、voltage |

GPIO1/3 留给串口，GPIO6–11 留给 flash。未把新外设接到启动配置脚 GPIO0/2/15，板载 LED 沿用原配置。D7 是普通数字输入；TLC549 暂停后不再占用它。

## 四只 LED

每一只外接 LED 都单独这样接，开关与 PWM 接法相同：

```text
对应 GPIO ── 1 kΩ ── LED 阳极 (+)
                         LED 阴极 (-) ── GND
```

共需四个限流电阻，不能让不同 LED 共用一个电阻。外接 LED 按高电平亮配置；板载 LED 的低电平逻辑由驱动单独处理。1 kΩ 是保守起点，通常亮度较低。例如假设某 LED 正向压降 2.0 V，3.3 V GPIO 下电流约 `(3.3−2.0)/1000 = 1.3 mA`；实际电流取决于 LED 型号与电平。

PWM **仍然必须串电阻**：每次导通瞬间承受的是高电平电压，调低占空比不能代替限流；100% 时就是持续点亮。0% 为持续关闭，100% 为持续点亮，中间值改变占空比，软件返回的是设置的占空比，不是光通量。

### 开关灯与调光灯联动

红色与绿色各有一组独立联动。对应的 `led.red/on` 或 `led.green/on` 为 `false` 时，`pwm.red/level` 或 `pwm.green/level` 每 250 ms 按电位器最近一次有效 raw 值更新，换算为 `round(raw × 100 / 1024)` 并限制在 0–100%；`GET /api/v1/state` 返回的 PWM 值就是实际值，安卓轮询后会覆盖滑块上的旧设置。此时手机发出的 PWM PUT 可能短暂改变输出，但下一次采样会恢复电位器值。

把某颜色的开关灯设为 `true` 后，固件停止该颜色的电位器覆盖，PWM 保持当前值并等待上位机新的 PWM PUT；把开关灯再次设为 `false` 时，如果已有有效电位器采样，则立即切回该采样值。红、绿两路互不影响。

## 电位器与 ADC

ESP8266 有 **一路 ADC**，通过 `analogRead(A0)` 读取；裸芯片输入范围为 0–1.0 V。某些开发板有输入分压，不能仅凭 V3 标识就把 3.3 V 直接接进 A0。原版 参考设计公开了 220 kΩ/100 kΩ 分压器，但不能据此认定用户这块板完全相同。

在尚未核实板载分压时采用如下保守接法：

```text
3V3 ────── 电位器一个固定端
GND ────── 电位器另一个固定端

电位器滑动端 ── 33 kΩ ──┬── A0
                        │
                       10 kΩ
                        │
                       GND
```

固定端与滑动端按电位器实际引脚/万用表结果确认，不按外观随意接线。先确认固定端总阻值，常见 10 kΩ 级电位器适合此信号接法，不要把未知低阻可变电阻直接跨接电源。按名义 3.3 V，外部分压上限约 `3.3 × 10/(33+10) = 0.77 V`，兼容裸芯片 1 V ADC 的限制；板载分压如存在，会使 ADC 读数进一步减小。没有 33 kΩ/10 kΩ 时，也可用四只 1 kΩ 串成上臂 4 kΩ、下臂 1 kΩ，上限约 0.66 V。不要用 5V/VIN 给电位器信号供电。

用户随后明确使用 3V3，0.4.0 按此作为板端换算基准：`电压估算 = round(raw × 3.3 / 1024, 3)`，同时显示原始计数与电压。512 对应 1.650 V，1024 对应 3.300 V。该算法是软件模型，未实测校准板载分压；3V3 供电与 A0 允许输入范围不是同一个事实。若仍采用上述额外分压，估算针对 A0 端，不自动还原分压前电位器滑动端电压。

raw 保留 SDK uint16 返回值，描述的最大值 65535 是返回值类型容量，不代表 16 位 ADC。超过标称 1024 时仍显示 raw，电压显示 unavailable，避免把超量程/未校准计数外推成确定电压。旧版超过 1023 就 unavailable 是软件规则，不是测到了硬件过压；计数与饱和不能证明实际电压或“只超出一点点”。

固件每 250 ms 采样一次，HTTP 只读取缓存，raw/voltage 同步生成；同值采样不增加 revision，值或可用性变化才增加一次。首次有效采样前两项均为 `null / unavailable`。负数或超出 SDK uint16 类型范围的结果使两项 unavailable；不能显示成 0。电位器断线可能产生浮空读数，单纯 ADC 无法可靠识别断线，不能把 good 当作接线健康诊断。

电位器与光敏信号不能直接并接到同一个 A0 来独立测量。A0 仅给电位器使用；TLC549 光敏方案暂缓启用，接线参考见 [TLC549 文档](tlc549.md)。

## 微波感应开关的继电器输入

这个模块的三个旋钮（定时、距离、光照阈值）仍由模块本身负责。ESP8266 读取它的二态输出：模块触发后继电器闭合，延时结束后释放，手机看到的是 `sensor.microwave.detected` 的只读状态和一次完整触发周期结束后更新的 `offDelayMs`（毫秒）。当前固件每 250 ms 轮询一次并由安卓正常读取 `/api/v1/state`，不会主动推送事件，也不会改变三个旋钮的设置；因此测量分辨率约为 250 ms。

固件按“常开、无源干接点”实现：D7/GPIO13 开启内部上拉，空闲开路读为 HIGH/`false`，触发闭合到 GND 读为 LOW/`true`。只有确认外露两线确实是继电器触点（或明确的 3.3 V 兼容开漏输出）后，才允许按下图接线：

```text
ESP8266 D7/GPIO13 ───────── 模块触点一端（COM）
ESP8266 GND       ───────── 模块触点另一端（NO）

模块空闲：触点开路，D7 被内部上拉为 HIGH，detected=false
模块触发：触点闭合，D7 被拉到 GND，detected=true
```

先断开两边电源，用万用表通断档确认“空闲开路、触发导通”。如果模块输出线带有 5 V、12 V、24 V、交流电或任何相对模块电源的电压，**不要接 D7，也不要为了测量把 ESP8266 GND 与未知电源硬连**；应改用额定电压/隔离等级匹配的光耦输入或合适的数字隔离模块，并重新确认接收侧输出不超过 3.3 V。两线若标成负载输出而不是 COM/NO 干接点，也不能按本图连接。检测到常闭逻辑时需先记录实测结果，再调整固件的有效电平并重新构建。

这个输入没有写接口，安卓面板只显示“检测到/未检测到”；它不能通过手机调节模块上的定时、距离和光照旋钮。若要远程调参，需要模块提供独立的数字/模拟配置接口，不能从现有两根继电器线推断。

### 板载 LED 自动控制与手机覆盖

每次采样到微波状态边沿时，固件让 `led.main` 跟随检测状态：检测到时点亮，恢复空闲时熄灭。手机仍可 PUT `led.main/on` 强制写入状态；该手动状态会保持到微波输入下一次发生状态变化，随后自动控制恢复。这样在一次检测持续期间，手机可以暂时关灯或开灯，不会被每一轮轮询立即覆盖；这不是永久“自动/手动模式”开关，重启后自动控制重新生效。

一次启动后观察到完整的 `false → true → false` 序列时，`offDelayMs` 记录从检测到释放之间的采样时间差。首次完整序列前该属性为 `null / unavailable`；后续周期完成后保留最近一次测量值。它是继电器输出的实测持续时间，不是旋钮刻度的理论值。

## 电机为何暂缓

两线小直流电机需要 **驱动电路**，但不一定要成品模块。单方向调速可使用合适的逻辑电平 MOSFET、续流二极管和门极偏置等组成驱动；也可使用匹配的电机驱动模块。需要独立的、适合电机额定电压及启动/堵转电流的电源，与控制器共地；不能用 GPIO 直接提供电机电流。

当前电机没有型号、额定电压/电流或驱动模块，不能据外观给定可用电压或驱动容量。本轮固件不声明 motor 资源，避免给出可以直连 GPIO 的误导。后续确认电机和驱动后，再确定 PWM/使能脚、限幅、启动行为、断联/控制超时停止策略；占空比不是实测转速。不要将当前灯光“断联保持”策略直接用于电机。

## 上电与联调

1. 断电按表接好四个独立电阻和 LED，电位器按保守分压方案接 A0；微波模块只在完成干接点/电压确认后接 D7；当前基础构建不启用 TLC549，暂不接光敏和电机。
2. 构建、上传当前基础固件（保留电压双属性与安卓 PWM 数值编码修复）。用户此前的 USB-SERIAL CH340 是 COM6；插拔后可能变化，以当前 IDE 端口为准。
3. 串口 115200 查看加入 SmartLife 后的 API 地址，在手机 App 发现/选择设备或手动连接。
4. 应出现板载 LED、两只开关灯、两只调光灯、电位器和微波感应输入，共 7 项。检查初始输出关闭、红绿互不影响；PWM 依次试 0/25/50/100/0；手动触发模块后观察 `detected` 从 false 变 true、板载 LED 点亮，再在延时后恢复 false、板载 LED 熄灭，并检查 `offDelayMs` 更新。
5. 转动电位器，核对 raw 与 voltage 同步变化；两项都不可写。raw 超过标称量程时记录具体数值，不能把属性最大值或软件估算当成 A0 的耐压指标。
