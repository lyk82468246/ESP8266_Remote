# NodeMCU V3 外设接线与控制

用户提供板卡文字：`LOLIN / wemos.cc / NEW NodeMCU V3`。使用现有 `nodemcuv2`（ESP-12E/ESP8266）构建基线；实际板卡未拍照或实测，不以该标识保证 A0 分压电路与原版完全一致。接线前断开电源。

## 安卓类型与本轮范围

| 外设 | 安卓分类与属性 | 本轮状态 |
| --- | --- | --- |
| 红、绿开关 LED | binary-output；boolean on | 已实现，两路独立 |
| 红、绿调光 LED | range-output；integer level，0–100%，step=1 | 已实现，两路独立，1 kHz 软件 PWM |
| 电位器 | sensor；只读 integer raw + number voltage（V） | 已实现，两项来自唯一 A0 的同一缓存 |
| 两线直流电机 | range-output，可用范围属性表示 PWM 占空比 | 缺少驱动与电机规格，本轮不注册、不分配输出 |
| 光敏器件 | sensor，具体属性依器件/电路确定 | 按用户决定延后，不与电位器并接 A0 |

板载 LED 保留，因此当前共 6 个资源，不是 8 个虚构外设。上位机按属性描述生成开关、滑块和只读值，无需写死本表 ID。上位机依据：[功能清单规范](https://github.com/zxu-source/Android_WIFI/blob/320f9c00b35aa7c80edd5911832b7a2ccd5c1c3b/docs/protocol/capability-list.md)。

## 引脚表

| 板上标记 | GPIO | 用途 | API 资源 / 属性 |
| --- | --- | --- | --- |
| D4 | 2 | 板载 LED，低电平亮，无需外接 | led.main / on |
| D1 | 5 | 第一只红 LED，开关 | led.red / on |
| D2 | 4 | 第一只绿 LED，开关 | led.green / on |
| D5 | 14 | 第二只红 LED，PWM | pwm.red / level |
| D6 | 12 | 第二只绿 LED，PWM | pwm.green / level |
| A0 | ADC | 电位器滑动端信号，经下述电压限制 | sensor.pot / raw、voltage |

GPIO1/3 留给串口，GPIO6–11 留给 flash。未把新外设接到启动配置脚 GPIO0/2/15，板载 LED 沿用原配置。D7 等剩余引脚本轮不使用。

## 四只 LED

每一只外接 LED 都单独这样接，开关与 PWM 接法相同：

```text
对应 GPIO ── 1 kΩ ── LED 阳极 (+)
                         LED 阴极 (-) ── GND
```

共需四个限流电阻，不能让不同 LED 共用一个电阻。外接 LED 按高电平亮配置；板载 LED 的低电平逻辑由驱动单独处理。1 kΩ 是保守起点，通常亮度较低。例如假设某 LED 正向压降 2.0 V，3.3 V GPIO 下电流约 `(3.3−2.0)/1000 = 1.3 mA`；实际电流取决于 LED 型号与电平。

PWM **仍然必须串电阻**：每次导通瞬间承受的是高电平电压，调低占空比不能代替限流；100% 时就是持续点亮。0% 为持续关闭，100% 为持续点亮，中间值改变占空比，软件返回的是设置的占空比，不是光通量。

## 电位器与 ADC

ESP8266 有 **一路 ADC**，通过 `analogRead(A0)` 读取；裸芯片输入范围为 0–1.0 V。某些开发板有输入分压，不能仅凭 V3 标识就把 3.3 V 直接接进 A0。原版 参考设计公开了 220 kΩ/100 kΩ 分压器，但不能据此认定用户这块板完全相同。

在尚未核实板载分压时采用如下保守接法：

```text
3V3 ────── 电位器一个固定端
GND ────── 电位器另一个固定端

电位器滑动端 ── 33 kΩ ──┬── A0
                        │
                       10 kΩ
                        │
                       GND
```

固定端与滑动端按电位器实际引脚/万用表结果确认，不按外观随意接线。先确认固定端总阻值，常见 10 kΩ 级电位器适合此信号接法，不要把未知低阻可变电阻直接跨接电源。按名义 3.3 V，外部分压上限约 `3.3 × 10/(33+10) = 0.77 V`，兼容裸芯片 1 V ADC 的限制；板载分压如存在，会使 ADC 读数进一步减小。没有 33 kΩ/10 kΩ 时，也可用四只 1 kΩ 串成上臂 4 kΩ、下臂 1 kΩ，上限约 0.66 V。不要用 5V/VIN 给电位器信号供电。

用户随后明确使用 3V3，0.4.0 按此作为板端换算基准：`电压估算 = round(raw × 3.3 / 1024, 3)`，同时显示原始计数与电压。512 对应 1.650 V，1024 对应 3.300 V。该算法是软件模型，未实测校准板载分压；3V3 供电与 A0 允许输入范围不是同一个事实。若仍采用上述额外分压，估算针对 A0 端，不自动还原分压前电位器滑动端电压。

raw 保留 SDK uint16 返回值，描述的最大值 65535 是返回值类型容量，不代表 16 位 ADC。超过标称 1024 时仍显示 raw，电压显示 unavailable，避免把超量程/未校准计数外推成确定电压。旧版超过 1023 就 unavailable 是软件规则，不是测到了硬件过压；计数与饱和不能证明实际电压或“只超出一点点”。

固件每 250 ms 采样一次，HTTP 只读取缓存，raw/voltage 同步生成；同值采样不增加 revision，值或可用性变化才增加一次。首次有效采样前两项均为 `null / unavailable`。负数或超出 SDK uint16 类型范围的结果使两项 unavailable；不能显示成 0。电位器断线可能产生浮空读数，单纯 ADC 无法可靠识别断线，不能把 good 当作接线健康诊断。

电位器与光敏信号不能直接并接到同一个 A0 来独立测量。以后可选择外置多通道 ADC 或模拟多路开关；目前仅电位器占用 A0。

## 电机为何暂缓

两线小直流电机需要 **驱动电路**，但不一定要成品模块。单方向调速可使用合适的逻辑电平 MOSFET、续流二极管和门极偏置等组成驱动；也可使用匹配的电机驱动模块。需要独立的、适合电机额定电压及启动/堵转电流的电源，与控制器共地；不能用 GPIO 直接提供电机电流。

当前电机没有型号、额定电压/电流或驱动模块，不能据外观给定可用电压或驱动容量。本轮固件不声明 motor 资源，避免给出可以直连 GPIO 的误导。后续确认电机和驱动后，再确定 PWM/使能脚、限幅、启动行为、断联/控制超时停止策略；占空比不是实测转速。不要将当前灯光“断联保持”策略直接用于电机。

## 上电与联调

1. 断电按表接好四个独立电阻和 LED，电位器按保守分压方案接 A0；暂不接电机与光敏器件。
2. 构建、上传当前固件（0.4.0 增加电压双属性，保留 0.3.1 的安卓 PWM 数值编码修复）。用户此前的 USB-SERIAL CH340 是 COM6；插拔后可能变化，以当前 IDE 端口为准。
3. 串口 115200 查看加入 SmartLife 后的 API 地址，在手机 App 发现/选择设备或手动连接。
4. 应出现板载 LED、两只开关灯、两只调光灯、电位器，共 6 项。检查初始输出关闭、红绿互不影响；PWM 依次试 0/25/50/100/0。
5. 转动电位器，核对 raw 与 voltage 同步变化；两项都不可写。raw 超过标称量程时记录具体数值，不能把属性最大值或软件估算当成 A0 的耐压指标。
