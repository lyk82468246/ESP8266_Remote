# PWM INVALID_VALUE 与安卓数值编码

日期：2026-10-16。修复固件：0.3.1。上位机检查提交：`320f9c00b35aa7c80edd5911832b7a2ccd5c1c3b`，与之前检查一致。只读取相关源文件，没有克隆、构建或修改安卓工程。

## 源码确认

- [ControlScreen.kt 第 158–173 行](https://github.com/zxu-source/Android_WIFI/blob/320f9c00b35aa7c80edd5911832b7a2ccd5c1c3b/app/src/main/java/edu/wifi/light/feature/control/ControlScreen.kt#L158-L173)：滑块使用属性 min/max，按 step 对齐，target 保存为 Double；数值输入也解析为 Double。没有把百分数除以 100。
- [Validation.kt 第 18–26 行](https://github.com/zxu-source/Android_WIFI/blob/320f9c00b35aa7c80edd5911832b7a2ccd5c1c3b/app/src/main/java/edu/wifi/light/domain/Validation.kt#L18-L26)：integer 要求值等于 round(value)，另校验有限、范围和步长，25.0 可通过整数语义检查。
- [ProtocolCodec.kt 第 113–117 行](https://github.com/zxu-source/Android_WIFI/blob/320f9c00b35aa7c80edd5911832b7a2ccd5c1c3b/app/src/main/java/edu/wifi/light/core/protocol/ProtocolCodec.kt#L113-L117)：数值通过 JsonPrimitive(Double) 编码，因此整数目标可能以 25.0 的形式发送。

本地 PWM 描述为 min=0/max=100/step=1/unit=%，因此 25 表示 25% 占空比；0.25 不是该整数属性下的 25%。

## 复现与修复

原固件使用 `JsonVariant.is<int32_t>()` 校验数字，拒绝解析为浮点类型的 25.0；此前测试把 25.0 归入非法值，这个预期过严。将测试首个 PWM 25% 写入改为 JSON 25.0，修复前在 `api.status() == 200` 处失败，复现 INVALID_VALUE。

0.3.1 先检查 JSON 数值类型，再验证有限、没有小数部分、在允许范围内，然后才转换为 int32 并校验步长。25、25.0、2.5e1 均可表示同一整数目标，回报仍为整数。字符串和 boolean 不转换，真实小数和越界数字不截断；boolean 输出继续只接受 JSON boolean。

本次没有抓取手机实际请求；诊断证据是上位机源码调用链和同一固件 API 的可重复测试，不声称完成手机真机修复验证。
